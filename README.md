# burningsuit.co.uk

A static Astro rebuild in progress. The homepage implements the approved homepage design, the Power BI with AI agents 101 page the agreed notebook direction, `/power-bi/` the approved consultancy page, `/training/` the training chooser built from accepted copy, `/training/power-bi-fundamentals/` the Fundamentals course page from approved copy, `/about/` the approved About copy, `/contact/` the approved Contact copy, `/training/how-i-train/` the approved How I train copy, `/hour/` the approved free 30-minute call page, and `/privacy/` the approved privacy notice; the rest of the site remains a compatibility shell. Nothing is approved for publication.

## Develop and check

Use Node 22.20+ and LF line endings. Install with `npm ci`, run `npm run dev`, and validate with:

```bash
npm run gate
npm run test:functional
```

The gate checks canonical brand parity, Astro types, source permissions, a static build, byte budgets, links, metadata, redirects and reserved anchors. Functional checks cover CSP, keyboard access, small screens, no-JavaScript behaviour, source permissions and the release block. Checks establish technical behaviour, not editorial approval.

Tests serve the existing `dist/`; build first. Each Playwright run chooses a fresh port and refuses to reuse an existing listener. Set `BURNINGSUIT_TEST_PORT` to pin Playwright's listener and `BURNINGSUIT_LINK_PORT` to pin the link checker's (which falls back to `BURNINGSUIT_TEST_PORT`); unset, each picks a free port. Use a separate checkout and fresh build for independent tests; never overwrite another review's build or stop its server. Leave the priced review at `127.0.0.1:4400` alone.

`npm run test:lh` and `npm run test:lh:mobile` audit the built bespoke pages for performance and accessibility. If Chrome is not on PATH, set `CHROME_PATH` to the installed browser executable. Functional tests attach full-page captures at 1366px and 390px for visual review; these are review artifacts, not approved screenshot baselines.

The link gate permits only the explicit future destinations in `src/config/pending-routes.mjs` while they have no built HTML; the list is currently empty. Add a reservation (and its 404 test follows automatically) for a linked page not yet built, and remove it when the page lands. Other broken internal links still fail. `/contact/` is a real page; the legacy `/get-in-touch` and `/get-touch` aliases redirect to it. About has no form of its own; its closing links offer email, the homepage enquiry form and LinkedIn. Home, Training, Power BI fundamentals, Consultancy and Contact share one form in `src/components/EnquiryForm.astro`: an optional name, a required email and a required message, with nothing preselected. Contact uses its options for the page `h1`, a two-paragraph introduction with the email above the form, and no email line below it; the other pages keep the `h2` heading and lower email fallback. Enquiry links on those pages jump to their inline `#contact` form, a plain POST. Formspark receives it at the public endpoint in `src/config/enquiry.mjs`; there is no API key or browser script. Email remains the fallback.

The form sets distinct `_redirect` and `_error` paths to `/enquiry-received/` and `/enquiry-error/`. `_append=false` prevents personal data entering redirect URLs; never remove it. CSP allows the endpoint's HTTPS origin and `'self'` so Chromium can follow the return redirect. A hidden `_gotcha` checkbox adds Formspark's native honeypot; automatic provider filtering also applies. No CAPTCHA is loaded. The enquiry-specific notice is `/privacy/enquiries/`; its field description matches the three fields, and it and the error page return to `/contact/`. The wider notice is `/privacy/`. A null endpoint disables Send and restores `form-action 'none'`. Noindex and the release block remain independent of form readiness.

`tests/enquiry.spec.ts` and `tests/contact.spec.ts` stub Formspark's redirect responses to check the no-JavaScript success/error journeys without sending email. Real delivery and spam-rejection checks are deliberate manual verification, not part of routine tests. If the provider itself is unreachable there is no redirect: the browser shows its network error; the email link on each form page remains the alternative. Keep any changed processing facts and retention instructions in the private ops privacy record as well as the notice.

Headings keep sentence case. The portrait uses `astro:assets` and the committed photo derivative; generated responsive images belong only in the build output.
- `src/components/seo/Schema.astro`: the retained JSON-LD emitter, with script-breakout escaping. Placeholder pages emit no schema or canonical links.
- Photos, diagrams, logos and social assets remain available. Sources are not automatically rendered.

Every page loads the cookieless Umami tag from `src/config/analytics.mjs`, which also feeds the CSP hosts; `data-domains` limits reporting to the production hostnames, so dev, test and preview hosts send nothing. It is the only third-party script, and tests allow exactly its URL. The only page script is the `/privacy/#optout` switch: a same-origin bundled module (never inlined; `astro.config.mjs` keeps bundled `.js` external) that sets or removes Umami's `umami.disabled` flag in `localStorage`, guarded against storage errors. Without scripting, `privacy.css` shows its fallback line instead. The switch stays hidden behind its fallback line until the module has wired it, so a failed script never leaves a dead button. `tests/privacy.spec.ts` covers the notice's words and anchors, the switch, the shared footer's company line and, by serving the build at the production address with Umami's beacon answered locally, that the switch stops counting. Umami's settings are read-only.

Tests never contact Umami. Specs import `test` from `tests/analytics.ts`, whose fixture serves the committed tracker copy in `tests/fixtures/umami/script.js` for the tag's URL and aborts any other Umami request, failing the test; `playwright.config.ts` also makes Umami's hosts unresolvable in the test browser. `UMAMI_LIVE=1` loads the real tag instead (beacons stay blocked). To refresh the copy, fetch the tag URL, replace the code under the file's header and update its date, version, ETag and hash; keep the MIT notice.

## Publication and safeguards

All shell pages are noindex; `robots.txt` disallows crawling. `npm run check:release` deliberately fails for the shell and is required by the production workflow before artifact upload. This is not a release candidate. Restore indexing, sitemap, substantive content, privacy controls and appropriate checks before a release is considered.

`main` publishes to GitHub Pages; `dev` is integration. Branches and Netlify previews can be public. Commit locally and ask before every push; a push, merge or deployment needs its existing authorization. Keep the local push-readiness hook enabled. The production workflow validates and tests one artifact before publishing it; the Netlify preview stays hard-noindexed. GitHub Pages cannot enforce HSTS or frame-ancestors through a meta CSP.

Local `AGENTS.md`, hooks and the private `design/` symlink remain untracked. Back up local instructions before a checkout/rebase over history that tracked them. Current website decisions live in the private brief, course scope in Practice, and voice/identity in the brand repo. Earlier implementations remain in git history; they are not current requirements.
